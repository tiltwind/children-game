# 全站玩法与运营规则

> 上层索引见 [../AGENTS.md](../AGENTS.md)。本文是**规则口径**（为什么这么设计、参数多少、边界怎么处理）；接入代码见 [shared-modules.md](shared-modules.md)。

这套规则的目的很明确：这是给小学生用的游戏合集，所以不是「防沉迷弹窗」式的软提示，而是**三套互相叠加的硬约束**，且都不能靠刷新、切页面、后退绕过。

## 1. 三套硬约束

| 规则 | 触发条件 | 惩罚 | 计数口径 | 实现 |
| --- | --- | --- | --- | --- |
| 强制休息 | 当日累计游玩 **30 分钟** | 全站休息 **10 分钟**，所有游戏不可操作 | 只在页面可见且有焦点时累计；菜单 / 暂停 / 结算 / 后台标签不计 | `playclock/` |
| 单游戏限次 | 单游戏**完整玩满 5 次** | 该游戏锁 **15 分钟**，可去玩别的游戏 | 一关 / 一局走完流程才 `count()`；失败、中途退出、重玩不计 | `limit/` |
| 局间门禁 | 单游戏（按页面）累计游玩 **5 分钟** | 弹全屏题，答对才解锁；答错必须继续答 | 只在实际游玩时 `tick()`；跨关卡累计；答题时长不计入门禁计时 | `gate/` |

三者是叠加而不是替代：一局游戏可能同时受「今日 30 分钟额度」「本游戏 5 次额度」「本页面 5 分钟门禁」约束，任意一条先到就先拦。

## 2. 强制休息（playclock）

- 参数：`PLAY_MS = 30 分钟`、`BREAK_MS = 10 分钟`，写在 `playclock.js` 顶部。
- 开始休息时：全屏遮罩（`z-index` 高于门禁与奖励弹窗）→ 捕获阶段拦截键盘 / 鼠标 / 触摸 / 滚轮 → 派发 `playclock:breakstart` 让各游戏暂停主循环。
- 休息结束时派发 `playclock:breakend`，各游戏恢复；**原本就手动暂停的游戏不被强行恢复**。
- 跨天自动清零当日累计；正在进行的休息不受跨天影响。
- 多标签页通过 `storage` 事件同步，休息全局生效。
- 首页只展示休息状态，不计时（`data-count="off"`）。
- 24 点页额外处理：休息期间暂停背景音乐，并把休息时长从答题计时里扣掉。

## 3. 单游戏限次（limit）

- 参数：`LIMIT = 5`、`LOCK_MS = 15 分钟`。
- `GameLimit.count(id)` 由游戏在**真正完成一局**时调用；`count` 在已达上限后不再累加。
- 失败 / 重跑是否计数由游戏自己决定，现网口径：
  - 枪战：每完成 1 关计 1 次；
  - 霓虹狂飙：每完整跑完 1 关计 1 次，**失败不计数**（允许无限重跑）；
  - 其余游戏按「完整一局」计。
- 锁定期间页面显示锁屏与倒计时，并提供回首页的入口；首页卡片同步显示剩余次数 / 锁定倒计时。
- 存档 `shutu.limit.v1`，结构 `{ games: { "<id>": { plays, lockUntil } } }`。

## 4. 局间门禁（gate）

- 参数：`everyMinutes = 5`（默认）；`allowSkip = false`（默认不给「换一题」）；`unlockDelay = 1000ms`。
- 题型按 `weight` 加权随机；现网答对后通过次数会累计，用于题型自身升难度（24 点升模式、口算升位数）。
- **门禁里的 24 点只用整数**：只走经典 → 进阶，不出「必须用分数」的题（显式配 `mode: "expert"` 也会降级为进阶）；题面、提示、判题全过程不允许出现分数中间结果。
- 答题规则：**答对才放行**。唐诗只能选一次，答错立即公布答案、8 秒后自动换题；口算答错不公布答案，连错两次给拆分提示。
- **防绕过**（这套规则的核心，改动时不得削弱）：
  - 计时进度与「未答对」状态每 2 秒落盘，`pagehide` / `beforeunload` / `visibilitychange` 立即落盘；
  - 刷新 / 关标签 / 隔天再来都不清零，接着计；
  - 门禁弹出但没答对就刷新 → 重新进入会**立刻再弹同类题**；
  - 「待通过」标记**全站共享**：A 游戏没答对就跑去看 B，B 页面挂载门禁时同样先拦；
  - 通过后 `pending` 清除、计时归 0。
- 门禁打开时 `Esc` 不能关闭。
- 存档按页面路径分键（`/tetris/tetris.html` 与 `/pvz/pvz.html` 各算各的）；同页多实例用 `game` 参数区分。

## 5. 关卡与难度设计原则

这些是被多款游戏验证过的共同取向，新增关卡时照着做：

1. **永远留出通路**。障碍只占部分车道 / 格子，任何时刻都有可走的缝隙（racing：锥桶、油桶、卡车都留缝；gun-game：房间与走廊必经连通校验）。
2. **难度用数据调，不用代码调**。pvz 的难度四件套 `speedMul` / `hpMul` / `sunStart`-`sunInterval` / `cooldownMul`，加每波 `groups` 的「数量 ×0.65、间隔 ×1.2」；racing 用每关 `par` 分决定 2★ / 3★ 门槛。调松紧只改表，不动逻辑。
3. **前 1–2 关必须是教学关**：只引入一个新机制，不叠加惩罚（gun-game OP.01 只教视野 / 掩体 / 处决）。
4. **机制单调递增，最后叠加**：单机制 → 组合 → 全叠加（racing 六关即 侧风 → 冰霜 → 雨战 → 极速 → 全叠加 + 追兵）。
5. **失败不惩罚重复**：失败不计数、不扣次数，鼓励重跑；限次只对「完整过关」计数。
6. **奖励与成长可见**：结算给星级 / 评级 / 信用点，并明确下一关解锁条件。
7. **单局时长控制在 3–8 分钟**：与 5 分钟门禁、5 次限次形成自然节奏。
8. **目标与状态必须在世界内可见**：抽象目标（计时圈、撤离点、终端）要画进场景并显示进度；出口未开放要有锁定视觉与一句解释；常驻一行「现在该做什么」（带方向与距离）。玩家不应靠猜或靠读小字判断自己卡在哪。
9. **同一关的节奏只挂一个时钟**：波次、计时、增援必须由同一个进度量驱动（例如防守关全部挂「圈内累计时间」），否则玩家拖延或提前清场时会掉进「无事可做」的空窗。
10. **收尾阶段必须能定位**：场上只剩一个目标时（最后一个敌人、最后一个终端、已开放的出口），要在世界内标出它并给出方位与距离；「差一个找不到」是最常见的流失点。出口与目标区同处一地的关卡（例如 OP.04 撤离点=降落圈），守满即结算，不要让玩家再跑一段没有信息的路。

## 6. 家长向体验约束

- 面向小学生：字号偏大、圆润字体、暖色系；24 点整页字号放大、暖色牌桌。
- 操作必须**键鼠 + 触屏双通道**：拖拽 / 点击按钮与键盘等价（racing 触屏拖动转向 + 右下角氮气键；pvz 点按种植 + 数字键选卡）。
- 答题反馈不直接公布答案（口算连错两次才给提示，唐诗答错两次才给篇名作者提示）。
- 音乐 / 音效开关独立，默认开启但可一键关闭，偏好写入存档。
- 文案语气：鼓励、不说教；规则页用一句话讲清「玩多久、休多久、几次后休息」。

## 7. 规则变更流程

改任何一条参数（30/10、5 次/15 分钟、5 分钟）时，必须同步以下位置，否则玩家看到的文案会和实际行为不一致：

1. `playclock/playclock.js` 顶部常量 与 `playclock/README.md`；
2. `limit/limit.js` 的 `LIMIT` / `LOCK_MS` 与 `limit/README.md`（若为空则补建）；
3. `gate/gate.js` 默认 `everyMinutes`、各游戏 `createGate()` 里的显式值、`gate/README.md` 的「已接入」表；
4. `index.html` 页头的 `.play-rule` / `.limit-rule` 两条文案；
5. 本文第 1 节的参数表、[../AGENTS.md](../AGENTS.md) 的规则速查表。
